# Adminpanel Conventions

Админ-панель — отдельное SPA для owner и администраторов: подбор пар, уведомления, места, жалобы, участники, статистика.

**Все правила из [`frontend/CONVENTIONS.md`](../frontend/CONVENTIONS.md) действуют и здесь** (mobile first, React Query по умолчанию, RTK по исключению, сетка Bootstrap классами, TypeScript, тесты, доступность). Ниже — только то, что отличается или уточняется.

## 1. Где и как работает

- Отдаётся Go-сервером по пути `/admin/` (Vite `base: '/admin/'`). Все ссылки и маршруты — относительно этого base, абсолютных `/…` в коде нет.
- Ходит только в `/api/admin/*` (и `/api/public/*` для справочников). API-клиент генерируется в `src/api` из `api/openapi.yaml`.
- Аутентификация — Bearer-токен по правилам `frontend/CONVENTIONS.md` §3a. Токен (`rl.admin.accessToken`) — в `sessionStorage`; с отметкой «Запомнить меня» на экране входа — в `localStorage`. При входе без отметки старый токен из `localStorage` удаляется.
- Ответ `401` с любого запроса → `clearToken()`, сброс кеша React Query и переход на `/admin/login` с возвратом на исходную страницу после входа.
- В `index.html` — `<meta name="robots" content="noindex">`.

## 2. Mobile first — тоже

Администратор часто работает с телефона: копирует текст уведомления и отправляет его в Telegram. Поэтому:
- Очередь уведомлений, подбор пары и очередь жалоб должны полностью работать на 360 px.
- Кнопки «Скопировать» и «Отправлено» — крупные, рядом с текстом. После копирования — короткое подтверждение (Toast).
- Списки на мобильном — карточки, на `md` и шире — таблицы (`.table-responsive`).
- Тяжёлые экраны (статистика с разрезами) могут быть удобнее на десктопе, но не ломаться на мобильном.

## 3. Состояние

- Серверные данные — React Query, как в `frontend`. После мутаций инвалидируются все затронутые ключи (например, создание пары → `queue`, `matches`, `notifications`).
- Фильтры, сортировка, вкладки и выбранный участник в очереди — в параметрах URL, чтобы ссылку на экран можно было переслать.
- `refetchOnWindowFocus: true` для очередей (уведомления, жалобы, ожидающие), чтобы при возврате во вкладку данные были свежими; для статистики — `false`.
- Конструктор пары (участники, сценарий, место, время, предпросмотр сообщений) — первый кандидат на RTK по критериям `frontend/CONVENTIONS.md` §2.3. Начинаем с `useReducer` внутри фичи и переходим на RTK, только если состояние понадобится нескольким экранам.

## 4. Структура

```
src/
├── app/            # провайдеры, маршруты, layout с навигацией, защита маршрутов
├── api/            # сгенерированный клиент (руками не править)
├── features/
│   ├── queue/          # ожидающие и кандидаты, создание пары
│   ├── matches/        # пары и встречи
│   ├── notifications/  # очередь ручной отправки
│   ├── participants/
│   ├── places/
│   ├── reports/
│   └── stats/
├── shared/
├── i18n/           # ru
└── styles/
```

## 5. Язык

- Интерфейс админки — на русском. Строки всё равно через `t('…')`, чтобы позже добавить языки без переписывания.
- Тексты уведомлений для участников приходят с сервера уже на языке участника; на клиенте их не переводим и не меняем.

## 6. Приватность и безопасность

- Персональные данные участников показываем только там, где они нужны для действия (Telegram username — в очереди уведомлений и карточке пары).
- В экспорт и в логи браузера — ничего персонального.
- Необратимые действия (удаление участника, блокировка, отмена пары) — только через модал подтверждения с названием действия на кнопке, не «ОК».
- Внутренние комментарии к жалобам и блокировкам видны только в админке и никогда не уходят в API участника.

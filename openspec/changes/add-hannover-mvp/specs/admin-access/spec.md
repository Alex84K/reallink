# Spec Delta

## Purpose

Даёт доступ к админ-панели (участники, подбор пар, встречи, статистика) только администраторам проекта и защищает админские действия.

## ADDED Requirements

### Requirement: Вход администратора
Система SHALL пускать администратора в админ-панель по email и паролю. Учётные записи администраторов создаются только через серверную команду; регистрации через интерфейс нет.

#### Scenario: Успешный вход
- **WHEN** администратор вводит верные email и пароль
- **THEN** система открывает сессию и показывает админ-панель

#### Scenario: Неверный пароль
- **WHEN** вводится неверный пароль
- **THEN** система отвечает общей ошибкой «неверный email или пароль», не уточняя, какое из полей неверно

### Requirement: Ограничение попыток входа
Система SHALL блокировать вход для email на 15 минут после 5 неудачных попыток подряд.

#### Scenario: Перебор пароля
- **WHEN** для одного email 5 раз подряд введён неверный пароль
- **THEN** шестая попытка в течение 15 минут отклоняется даже с верным паролем

### Requirement: Сессия администратора
Сессия администратора SHALL истекать через 7 дней или после выхода. Все админские операции MUST отклоняться без действующей сессии.

#### Scenario: Доступ без сессии
- **WHEN** запрос к админскому API приходит без действующей сессии
- **THEN** система отвечает ошибкой авторизации и не выполняет действие

#### Scenario: Выход
- **WHEN** администратор нажимает «Выйти»
- **THEN** сессия завершается, и повторный запрос с ней отклоняется

### Requirement: Журнал админских действий
Система SHALL записывать в журнал, кто и когда создал или отменил пару, изменил встречу, перевыпустил ссылку участника или удалил участника.

#### Scenario: Удаление участника администратором
- **WHEN** администратор удаляет участника
- **THEN** в журнале появляется запись с администратором, временем и действием, без персональных данных удалённого участника

# Proposal

## Why

Целевая аудитория — релоканты и диаспоры — живёт в Telegram: там их чаты и каналы, через которые owner ведёт привлечение. Веб-MVP (`add-hannover-mvp`) требует от администратора вручную отправлять каждое уведомление и не даёт открыть продукт прямо из Telegram. Mini App и бот убирают ручную работу и снижают порог входа.

Зависимость: change применяется после `add-hannover-mvp` и его архивации, потому что изменяет его capabilities.

## What Changes

- Telegram Mini App как второй вход в тот же профиль: анкета с предзаполнением из Telegram, затем страница участника без ссылки и пароля.
- Привязка Telegram к профилю, созданному через веб.
- Автоматическая доставка уведомлений через бота; ручная очередь остаётся запасным путём, когда бот не может доставить сообщение.
- Язык интерфейса по умолчанию — из Telegram; источник регистрации — из параметра запуска Mini App; канал регистрации (веб или Telegram) в статистике.

Вне scope: чат через бота, групповые чаты, оплата через Telegram, команды бота кроме `/start`.

## Capabilities

### New Capabilities

- `telegram-access`: вход через Mini App, проверка данных запуска, привязка Telegram-аккаунта, отказ заблокированным.

### Modified Capabilities

- `notifications`: доставка через бота; ручная очередь — только для недоставленных.
- `participant-registration`: username и язык из Telegram, источник из параметра запуска, канал регистрации, удаление Telegram ID.
- `admin-stats`: разрез по каналу регистрации.

## Impact

- Внешняя зависимость: Telegram Bot API (один бот для Mini App и уведомлений), webhook на сервере.
- Server: новый срез `telegram` (initData, бот, webhook), воркер доставки в срезе `notify`, миграция (`telegram_user_id`, `channel`, коды привязки).
- Frontend: слой `src/telegram` (режим, initData, тема, BackButton и MainButton).

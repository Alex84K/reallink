# Spec Delta

## ADDED Requirements

### Requirement: Доставка через бота
Система SHALL отправлять уведомление через Telegram-бота, если у участника привязан Telegram и он не заблокировал бота. Сообщение содержит кнопку, открывающую страницу участника в Mini App. Каждое уведомление MUST доставляться не больше одного раза; при временной ошибке Telegram система SHALL повторять отправку до 24 часов.

#### Scenario: Уведомление в Telegram
- **WHEN** создана пара, и у A привязан Telegram
- **THEN** A получает сообщение от бота с кнопкой «Открыть», а уведомление отмечается отправленным без участия администратора

#### Scenario: Временная ошибка Telegram
- **WHEN** Telegram вернул временную ошибку
- **THEN** система повторяет отправку и доставляет сообщение один раз

## MODIFIED Requirements

### Requirement: Очередь отправки
Система SHALL показывать администратору очередь уведомлений, которые нельзя доставить через бота (Telegram не привязан, бот заблокирован, повторы исчерпаны), — сначала самые старые, с получателем, его Telegram username, событием, причиной и готовым текстом с кнопкой «Скопировать». Каждое событие MUST давать не больше одного уведомления на получателя.

#### Scenario: Отправка вручную
- **WHEN** администратор копирует текст, отправляет его участнику в Telegram и нажимает «Отправлено»
- **THEN** уведомление отмечается отправленным и исчезает из очереди

#### Scenario: Повтор события
- **WHEN** одно и то же событие обрабатывается повторно
- **THEN** второе уведомление для того же получателя не создаётся

#### Scenario: Участник заблокировал бота
- **WHEN** Telegram отвечает, что пользователь заблокировал бота
- **THEN** уведомление сразу попадает в ручную очередь с причиной «бот заблокирован»
